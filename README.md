# handoff

[![CI](https://github.com/0301sdh/handoff/actions/workflows/ci.yml/badge.svg)](https://github.com/0301sdh/handoff/actions/workflows/ci.yml)

AI 코딩 작업의 **목표·주의사항·진행 기록을 파일로 관리하고, 새 세션에 전달하는 CLI 도구**입니다.
Claude Code, Codex, GitHub Copilot CLI에 시작 훅과 마무리 스킬을 설치할 수 있습니다.

## 동작 방식

### 해결하려는 문제

- 새 세션에서 이전 대화가 전달되지 않으면 목표와 진행 상황을 다시 설명해야 합니다.
- 작업이 길어지면 처음 정한 목표나 주의사항을 놓치기 쉽습니다.
- 작업 기록이 없으면 다음 날 무엇을 왜 결정했는지 파악하기 어렵습니다.

handoff는 목표와 규칙을 파일에 남기고, 작업을 시작할 때 필요한 기록을 모아 AI에게 전달합니다.
작업을 마칠 때는 AI가 변경 사항을 점검하고 다음 세션을 위한 기록을 남기도록 지시합니다.

### 역할 분담

| 주체 | 역할 |
|---|---|
| 프로그램 | 기본 파일 생성, 시작용 맥락과 마무리 지시 조합, 기록의 형식·누락 검사 |
| AI | 실제 코드와 변경 사항 점검, 작업 요약, 로그 작성, 완료 조건 갱신 |
| 개발자 | 목표·주의사항 설정, AI의 판단과 기록 검토 |

## 설치와 AI 도구 연결

### 공통 설치

Node.js 22 이상이 필요합니다. 아직 npm에 배포하지 않았으므로 저장소에서 빌드해 설치합니다.

```bash
git clone https://github.com/0301sdh/handoff.git
cd handoff
npm ci
npm run build
npm link
```

`npm link`가 `handoff` 명령을 전역에 연결합니다. 지우려면 `npm uninstall -g handoff`를 실행합니다.

### AI 도구 연결

**handoff 저장소가 아니라 작업할 프로젝트 폴더**에서 쓰는 도구를 연결합니다. `--agent`를 반복하면 여러 도구를 함께 연결할 수 있습니다.

| 도구 | 연결 | 마무리 호출 | 참고 |
|---|---|---|---|
| Claude Code | `handoff init --agent claude` | `/handoff-end` | `handoff end` 결과가 바로 전달됩니다 |
| Codex | `handoff init --agent codex` | `$handoff-end` | 처음 한 번 `/hooks`에서 훅을 신뢰해야 합니다 |
| Copilot CLI | `handoff init --agent copilot` | `/handoff-end` | 시작 훅이 `handoff start --json`을 사용합니다 |

기존 설정과 기록은 유지하며, 여러 번 연결해도 중복 설치하지 않습니다.

## 기본 작업 흐름

### 1. 초기화하고 목표와 규칙 작성하기

연결 명령을 실행하면 `.handoff/`에 기본 파일이 생성됩니다.
`.handoff/spec.md`에 목표와 완료 조건을, `.handoff/rules.md`에 주의사항을 채웁니다.
직접 작성하거나 AI에게 초안을 부탁한 뒤 검토합니다.

로그인 기능을 만든다면 목표 파일의 완료 조건을 다음처럼 작성합니다.

```markdown
## 완료 조건
- [ ] 올바른 계정으로 로그인할 수 있다
- [ ] 잘못된 비밀번호로 로그인하면 오류를 안내한다
```

주의사항에는 `- [R1] 비밀번호를 로그에 출력하지 않는다`처럼 번호를 붙입니다.

### 2. 새 세션에서 작업 시작하기

AI 도구에서 새 세션을 엽니다. 시작 훅이 실행되면 지침·목표·주의사항·최신 기록이 전달됩니다.
AI와 오늘 작업할 범위를 확인하고 개발을 진행합니다.

### 3. 마무리하고 기록 검토하기

마무리 스킬을 호출하면 AI가 변경 사항을 점검해 날짜별 로그를 쓰고, `handoff check`로 누락을 확인합니다.
개발자는 AI가 작성한 기록과 완료 조건 변경을 검토합니다.

### 4. 다음 세션에서 이어가기

다음 날 시작 훅은 최신 로그를 목표·주의사항과 함께 전달합니다.
AI는 이를 바탕으로 남은 로그인 실패 처리를 이어갈 수 있습니다.

### 연결 없이 사용하기

`handoff init`으로 초기화한 뒤 아래 명령의 출력을 AI 대화에 직접 전달할 수도 있습니다.

```bash
handoff start   # 작업을 시작할 때 전달할 내용
handoff end     # 작업을 마칠 때 전달할 지시
```

## 명령어

| 명령어 | 하는 일 |
|---|---|
| `handoff init` | `.handoff/` 폴더와 기본 파일을 만듭니다. 이미 있으면 아무것도 바꾸지 않습니다 |
| `handoff init --agent <이름>` | 초기화와 함께 AI 도구 연결 설정을 설치합니다. 기존 `.handoff/`가 있으면 그대로 두고 연결만 진행합니다 |
| `handoff start` | AI에게 줄 맥락을 출력합니다. 최신 로그는 내용을, 이전 로그는 경로만 포함합니다 |
| `handoff start --json` | 맥락을 `{"additionalContext": "..."}` 형식으로 출력합니다. Copilot 훅이 사용합니다 |
| `handoff end` | AI에게 줄 마무리 지시를 출력합니다. 기록은 AI가 직접 씁니다 |
| `handoff check` | 가장 최근 기록에 빠진 항목이 없는지 검사합니다 |
| `handoff --help` | 명령과 옵션의 사용법을 출력합니다 |
| `handoff --version` | 현재 버전을 출력합니다 |

모든 명령은 대상 프로젝트 폴더 안에서 실행합니다.
종료 코드는 `0` 성공, `1` 작업 실패 또는 문제 발견, `2` 잘못된 사용법입니다.

## 파일 구성과 기록 형식

```text
.handoff/
├── spec.md          # 목표, 완료 조건, 범위 밖, 참고 문서, 변경 기록
├── rules.md         # 주의사항: [R1], [R2]처럼 번호를 붙입니다
├── INSTRUCTIONS.md  # AI가 따를 작업 순서와 기록 형식
└── logs/
    └── 2026-11-04.md # 날짜별 작업 기록
```

### 참고 문서

API 명세, 화면 설계처럼 작업할 때 따라야 할 문서를 `spec.md`에 "언제 읽을지"와 함께 등록할 수 있습니다.

```markdown
## 참고 문서
- [D1] docs/api.md: API를 만들거나 고칠 때
- [D2] https://figma.com/...: 화면을 만들 때
```

작업 지침은 AI에게 해당 작업 시 문서를 읽고, 마무리할 때 구현과 대조하도록 요청합니다.
`handoff check`는 로컬 경로의 존재 여부와 문서별 점검 기록을 확인합니다. 외부 링크에 접속하거나 문서 내용과 구현을 비교하지는 않습니다.

### 날짜별 기록

로그는 지난 대화 전체가 아니라 작업 내용·결정 이유·점검 결과·다음 할 일을 요약한 인수인계 기록입니다.
작성 형식은 `.handoff/INSTRUCTIONS.md`에 있습니다.

`handoff check`는 유효한 날짜 이름의 로그 중 가장 최근 기록에서 다음을 검사합니다.

- `오늘 한 일`, `결정한 것`, `주요 대화`, `완료 조건 점검`, `주의사항 점검`, `다음 할 일` 제목이 모두 있는지
- `spec.md`의 체크박스 완료 조건마다 해당 문구로 시작하는 점검 항목이 있는지
- `rules.md`의 `[R1]`, `[R2]` 같은 규칙 번호마다 점검 항목이 있는지
- 등록된 참고 문서가 있으면 `참고 문서 점검` 제목과 문서 번호별 점검 항목이 있는지
- `다음 할 일`에 목록 항목이 있는지
- 로그 폴더의 Markdown 파일 이름이 `YYYY-MM-DD.md` 형식의 실제 날짜인지

## 개발과 테스트

```bash
npm ci
npm run typecheck   # 타입 검사
npm run lint        # 린트
npm run build       # dist/에 빌드
npm test            # 테스트
```

GitHub Actions는 `main` 브랜치에 push하거나 PR을 생성·업데이트할 때 Node.js 22와 24에서 타입 검사·린트·빌드·테스트를 실행합니다.

| 파일 | 역할 |
|---|---|
| `src/bin.ts` | 실행 파일의 입구 |
| `src/cli.ts` | 옵션 해석, 사용법 검사, 결과 출력 |
| `src/init.ts` | `.handoff/` 만들기 |
| `src/agents.ts` | AI 도구별 훅과 스킬 설치 |
| `src/start.ts` | 맥락 만들기 |
| `src/end.ts` | 마무리 지시 만들기 |
| `src/check.ts` | 기록 검사 |
| `src/logs.ts` | 기록 파일 이름 검사 |

핵심 기능 함수는 결과만 반환하고, 출력과 종료 코드는 `cli.ts`가 정합니다. 그래서 테스트에서 결과를 바로 비교할 수 있습니다.
